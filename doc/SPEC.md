# 通勤サウンドスケープ アプリ制作指示書（Claude Code向け）

## 1. 概要とコンセプト

移動中の「場所」を楽譜にして、癒し系インストゥルメンタルを端末上で自動生成・再生するAndroidアプリを作る。経路の登録は不要で、約5分ごとの位置情報から曲を作り、あらかじめ登録した地点に近づくと曲が変化する。

- **コンセプト**：「場所が楽譜になる」。約1km四方のマスごとに固有のメロディがあり、同じ場所では同じメロディが鳴る。自宅・職場・好きな公園などの登録地点に近づくと、その地点のテーマが聞こえてきて、着くと曲が着地する
- **Endel / Brain.fm との違い**：両者は「今の状態（時間・天気・心拍、集中・睡眠）」に合わせる音。本アプリは「場所」に合わせる音で、よく行く場所ほど自分だけのなじみのメロディになる
- **前提**：Web試作（Web Audio API、ルールベース生成）で音の方向性とバックグラウンド再生の方式を検証済み。試作は経路型だったが、音作りと再生方式はそのまま流用する
- **生成方式**：AIモデルではなく、和音・音階・リズムをプログラムで組み合わせるルールベース合成。オフラインで動き、API費用がかからない

## 2. MVPのスコープ

MVPは「経路を登録せずに再生でき、画面オフでも途切れず、登録地点に近づくと音が変わる」ことを満たす。

| 区分 | 内容 |
| --- | --- |
| 作る | 約5分ごとの位置情報から音楽を生成する機能（5章） |
| 作る | 地点の登録（最大20件）と、近づいたときの音の変化（6章） |
| 作る | 画面オフでも途切れないバックグラウンド再生（フォアグラウンドサービス） |
| 作る | ロック画面・通知からの再生/一時停止 |
| 作る | 再生画面、地点の一覧・登録画面 |
| 作らない | 経路（ルート）の登録、駅単位の演出、地上/地下の判定 |
| 作らない | iOS版、アカウント、クラウド同期 |
| 作らない | 音の日記（移動記録の保存）、他ユーザーとの共有 |
| 作らない | 歩行リズム・明るさ・騒音などの追加入力（将来の拡張） |

## 3. 技術方針

Androidネイティブ（Kotlin）で作り、音声は自前で合成したPCMを `AudioTrack` に隙間なく流し込む。Web試作で、Chromeの画面オフ時にリアルタイム生成が途切れることを確認したため、OSに正式に守られる再生経路を使う。

| 項目 | 採用するもの | 理由 |
| --- | --- | --- |
| 言語・UI | Kotlin、Jetpack Compose | 標準構成でClaude Codeが扱いやすい |
| 最小SDK | API 26（Android 8.0）以上 | フォアグラウンドサービスとAudioTrackの安定動作 |
| 音声出力 | `AudioTrack`（ストリーミングモード、PCM 16bit、44.1kHz、ステレオ） | 生成したバッファを隙間なく連結できる |
| 音声合成 | Kotlinで自前実装（オシレーター、エンベロープ、フィルター、ディレイ、リバーブ） | 外部依存なし、試作の音を再現しやすい |
| バックグラウンド | フォアグラウンドサービス（サービス種別は mediaPlayback と location の両方） | 画面オフ・他アプリ使用中も継続 |
| メディア操作 | Media3 の `MediaSession` | ロック画面・通知・Bluetoothイヤホンのボタン対応 |
| 位置情報 | Fused Location Provider（`PRIORITY_BALANCED_POWER_ACCURACY`、通常5分間隔） | 省電力で、場面の決定には十分な精度 |
| 地点への接近検知 | 位置の取得間隔を可変にして距離で判定（通常5分、登録地点の1.5km以内では1分） | 「常に許可」の位置権限が不要で、ジオフェンスより反応の遅れが読みやすい |
| 保存 | Room（登録地点、訪問履歴） | 端末内だけで完結させる |

- 音声合成はUIスレッドから切り離し、専用スレッド（またはコルーチンの `Dispatchers.Default`）で行う
- オーディオフォーカスを取得し、電話着信・他アプリ再生時は一時停止する
- イヤホンが抜けたら（`ACTION_AUDIO_BECOMING_NOISY`）一時停止する
- GitHub Actions でデバッグ用APKをビルドし、成果物としてダウンロードできるようにする（スマホで直接インストールして試すため）

## 4. 音楽生成エンジンの仕様

Web試作の値をそのまま初期値として移植する。すべての値は定数ファイルにまとめ、あとで調整できるようにする。

### 基本設定

- 調：Fメジャー（ルート音 MIDI 53 = F3）
- 1拍 = 0.9秒（約67BPM）が基準。場面や地点の雰囲気で0.8〜1.1秒に変える。和音は8拍ごとに切り替え
- メロディ音域：MIDI 65〜86 のFメジャー・ペンタトニック（F, G, A, C, D）
- 乱数はシード付き（例：Mulberry32）にし、同じシードなら同じ結果になるようにする

### 和音（ルートからの半音数）

| 名前 | 構成音 |
| --- | --- |
| I | 0, 4, 7, 11, 14 |
| IV | 5, 9, 12, 16, 19 |
| vi | 9, 12, 16, 19 |
| ii | 2, 5, 9, 12, 16 |
| iii | 4, 7, 11, 14 |
| Vsus | 7, 12, 14, 17 |

### 曲の状態（フェーズ）

| 状態 | いつ | 和音進行 | 1拍あたりのメロディ発音確率 |
| --- | --- | --- | --- |
| 始まり | 再生開始から1分間 | I → IV | 0.18 |
| 道中 | 通常時 | vi → IV → I → Vsus → ii → iii → IV → I | 場面で決まる（5章） |
| 区切り | 道中が20分続くごとに1回 | IV → Vsus → IV → I | 0.38 |
| 接近 | 登録地点の外側の円に入った | IV → Vsus → IV → I を繰り返す | 0.38 |
| 到着 | 登録地点の内側の円に入った | I を長く鳴らして着地 | 0.2 |
| 滞在 | 到着後、外側の円を出るまで | I → IV → vi → IV | 0.2 |
| 終わり | 停止ボタン | I を鳴らして約12秒でフェードアウト | なし |

状態が変わったら、次の和音の切り替え時に新しい進行の先頭から始める。発音は拍の頭と裏（0.5拍）で判定し、裏は確率を0.6倍にする。

### 音色

| パート | 作り方 | 役割 |
| --- | --- | --- |
| パッド | 三角波2本（±6セント）→ ローパス1400Hz、立ち上がり2.5秒、余韻3.5秒 | 和音の土台 |
| ベース | サイン波、和音の根音を1オクターブ下で、立ち上がり3秒 | 低音の支え |
| プラック | 三角波、2.2秒で指数減衰、左右にランダム定位 | メロディ |
| ベル | サイン波の倍音（×1、×2.76、×5.4）、減衰4秒 | 場所・地点のモチーフ |

- 全体にディレイ（0.675秒、フィードバック0.32、ローパス2200Hz）とリバーブ（残響3.5秒程度）をかける
- メロディは直前の音から7半音以内で、現在の和音の構成音を優先して選ぶ（和音外の音は35%の確率で許可）
- 最後にコンプレッサーで音量をならす

### モチーフ

3〜4音の短いメロディで、ペンタトニック内の音から作る。2種類ある。

- **場所のモチーフ**：約1km四方のマスごとに、マスのIDをシードに自動生成する。場面の切り替え時にベルで0.5拍間隔で鳴らし、道中では24拍ごとに直前の場面のモチーフをプラックで静かに再現する
- **地点のテーマ**：登録地点ごとに持つ（6章）。最後の音は主音（F）で終わるようにし、到着時の着地感を出す

## 5. 入力と場面

約5分ごとの位置確認を「場面」の区切りとし、その場面のモチーフ・テンポ・発音確率・音色を決める。

| 要素 | 算出方法 | 音への反映 |
| --- | --- | --- |
| 場所 | 緯度経度を約1km四方のマス（ジオハッシュ6桁）に変換 | 場所のモチーフを決める。同じマスでは常に同じモチーフ |
| 移動の速さ | 前回の位置との距離 ÷ 経過時間 | 静止（時速0.5km未満）：1拍1.1秒、発音確率0.2／徒歩（時速7kmまで）：1拍0.9秒、0.4／乗り物（時速7km以上）：1拍0.8秒、0.55 |
| なじみ度 | 端末内の訪問履歴で、そのマスを訪れた日数 | 初めての場所：高音のベルの装飾を加える／10日以上訪れた場所：パッド中心で音数を減らす |
| 太陽の高さ | 緯度経度と時刻から太陽高度を計算（通信不要） | 夜（高度-6°未満）：全体ローパス2500Hz、和音を1オクターブ下げる／薄明（-6°〜6°）：4000Hz／昼：6000Hz |

- 場面の切り替えは次の和音の区切りで行い、テンポ・発音確率・フィルターは8拍かけて徐々に移す
- 地下や屋内で位置が取れない場合は直前の場面を続け、速度も直前の値を維持する
- 位置の許可がない場合は、太陽の高さ（端末のタイムゾーンから概算）と経過時間だけで生成する。地点の演出は使えない旨を画面に出す

## 6. 登録地点と接近時の変化

自宅・職場・公園など、ユーザーが登録した地点に近づくと曲が変化する。

### 登録内容

```json
{
  "id": "b3f1…",
  "name": "いつもの公園",
  "lat": 35.0000,
  "lng": 139.0000,
  "approachRadius": 500,
  "arriveRadius": 100,
  "mood": "calm",
  "themeSeed": 12345
}
```

- 登録方法は「現在地で登録」と「地図をタップして登録」の2通り。名前は自由入力
- 登録できるのは最大20件
- 半径は、接近（外側の円）200〜1000m、到着（内側の円）50〜300mの範囲でスライダー調整。既定値は500mと100m
- テーマは `themeSeed` から生成する。編集画面に「試聴」と「別のメロディにする」（シードを振り直す）ボタンを置く

### 雰囲気（mood）

| 雰囲気 | 音の変化 |
| --- | --- |
| 落ち着く（calm） | 1拍1.0秒、全体ローパス3500Hz、発音確率を0.8倍 |
| 明るい（bright） | 1拍0.85秒、メロディ音域を1オクターブ上まで広げ、ベルの装飾を増やす |
| 懐かしい（nostalgic） | 滞在中の進行を vi → IV → I → iii にし、ディレイのフィードバックを0.45に上げる |

### 近づいたときの流れ

| 段階 | きっかけ | 音の変化 |
| --- | --- | --- |
| 接近 | 外側の円に入る | 接近フェーズに移り、地点の雰囲気の音色へ16拍かけて移行。8拍ごとに地点のテーマをプラックで小さく鳴らす |
| 到着 | 内側の円に入る | 地点のテーマをベルで鳴らし、I で着地。その後は滞在フェーズ |
| 離れる | 外側の円から出る | 地点のテーマを一度だけ静かに鳴らし、16拍かけて道中に戻る |

- 判定は位置を取得するたびに、全地点との距離を計算して行う。登録地点の1.5km以内にいる間は取得間隔を1分に短縮する
- 円の境目でのばたつきを防ぐため、外に出た判定は半径の1.2倍を超えてからにする。同じ地点の接近演出は、離れてから30分以内は繰り返さない
- 複数の地点の円が重なる場合は、内側の円に入っている地点を優先し、それもなければ距離が近い地点を優先する
- 再生開始時にすでに内側の円の中にいる場合は、始まりの代わりに滞在フェーズから始める
- 乗り物で速く通過した場合は、接近の判定が間に合わないことがある。その場合は到着だけを演出する

## 7. チャンク生成とバッファ設計

音は10秒単位のチャンクで先回りして作り、常に30〜60秒ぶんを再生待ちに置く。これで再生開始は1秒以内、画面オフでも途切れず、位置の変化にも1チャンク遅れで追従できる。

処理の流れ：位置・時刻の入力 → 状態の更新（場面・フェーズ・地点）→ 作曲（拍ごとの音符イベント）→ 合成（10秒のPCMチャンク）→ バッファ（30〜60秒）→ AudioTrack

作曲（音符を決める）と合成（波形を作る）を分けておくと、先読み中に状態が変わっても未合成の部分だけ作り直せる。

- **つなぎ目**：シンセの状態（鳴っている音の残り、ディレイ・リバーブの内部バッファ、フィルターの状態）をチャンクをまたいで引き継ぐ。チャンクごとに新しく作り直さない
- **開始**：最初のチャンクは2秒ぶんだけ先に合成してすぐ再生し、残りは再生しながら埋める
- **状態の変化**：場面の切り替えや地点への接近・到着は、未合成の作曲イベントを破棄して作り直し、次に合成するチャンクから反映する（最大10秒の遅れは許容）
- **バッファ不足**：生成が追いつかなかった場合は無音を挟まず、直前のパッドを伸ばしてつなぐ
- **メモリ**：44.1kHzステレオ16bitで60秒 ≒ 10.6MB。長時間再生しても常にこの上限に収める

## 8. バッテリー・位置情報・プライバシー

目標は「普段の音楽アプリの再生と同程度の消費」。位置情報は必要なときだけ細かく取る。

- 位置の取得間隔は通常5分、登録地点の1.5km以内では1分。精度は `PRIORITY_BALANCED_POWER_ACCURACY` で、高精度GPSは使わない
- 合成はバッファが30秒を切ったときにまとめて行い、それ以外はスレッドを休ませる
- 画面オフ中はUIの更新を止める
- 一時停止中は位置の取得と合成を両方止め、停止したらフォアグラウンドサービスを終了する
- 訪問履歴として保存するのはマスIDと訪問日だけ。正確な緯度経度や移動の軌跡は保存しない
- 登録地点の座標と訪問履歴は端末内（Room）にだけ保存し、外部に送信しない
- 設定画面に「訪問履歴を消去」ボタンを置く

### 必要な権限

- `ACCESS_FINE_LOCATION` と `ACCESS_COARSE_LOCATION`（アプリ使用中の許可で足りる。サービスはユーザー操作から起動するため、「常に許可」は求めない）
- `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MEDIA_PLAYBACK`、`FOREGROUND_SERVICE_LOCATION`
- `POST_NOTIFICATIONS`（Android 13以上、再生中の通知のため）

## 9. 画面仕様

| 画面 | 表示・操作 |
| --- | --- |
| 再生 | 経過時間、現在の場面（例：「歩いている・なじみの場所・夕方」）、次の場面までの残り時間、一番近い登録地点と距離（接近中は「いつもの公園に近づいています」）、再生/一時停止ボタン、停止ボタン |
| 地点の一覧 | 登録地点の一覧、追加・編集・削除、各地点のテーマの試聴 |
| 地点の登録・編集 | 名前、位置（現在地／地図タップ）、雰囲気3択、接近・到着の半径、テーマの試聴と作り直し |
| 設定 | 訪問履歴の消去、デバッグ表示の切り替え |
| 通知・ロック画面 | タイトル「通勤のサウンドスケープ」、サブタイトルは通常「おまかせ再生中」、接近中は「○○に近づいています」、再生/一時停止 |

- 配色の初期値：背景 #E4E9E7、文字 #25323B、アクセント #6F9A8D、ハイライト #D39A2E。ダークモードでは背景 #1B2328、文字 #E2E8E5、ハイライト #E3B45A
- フォントは丸ゴシック系（Zen Maru Gothic を同梱、なければ端末標準）
- 開発用に「デモ再生」を用意する。5分の場面を30秒に縮め、架空の移動（自宅 → 公園 → 駅 → 職場）で場面の切り替え、接近、到着、滞在、離脱を擬似的に起こす

## 10. 実装ステップ

5段階で進め、各段階の完了条件を満たしてから次へ進む。各段階の終わりに実機（Android）での確認手順を README に追記すること。

| 段階 | 作るもの | 完了条件 |
| --- | --- | --- |
| 1. 音の再現 | 合成エンジン（4章）とデモ再生、APKビルド用のGitHub Actions。位置なし、画面オンのみ | デモ再生が途切れず鳴り、始まり・道中・接近・到着・滞在・終わりの違いが聞き分けられる |
| 2. バックグラウンド | チャンク生成とバッファ（7章）、フォアグラウンドサービス、MediaSession | 画面オフのまま30分間、音切れなしで再生できる。ロック画面から一時停止・再開できる |
| 3. おまかせ再生 | 5分ごとの位置取得、場面の決定、ジオハッシュ変換、訪問履歴、太陽高度の計算 | 30分以上移動して、5分ごとに場面が音切れなく切り替わり、同じ場所に戻ると同じモチーフが鳴る |
| 4. 登録地点 | 地点の一覧・登録画面と保存、取得間隔の切り替え、接近・到着・離脱の判定と演出 | 登録地点に歩いて近づくと、外側の円に入ってから2分以内に接近の演出が始まり、内側の円で到着の演出が鳴る |
| 5. 仕上げ | 画面のデザイン、オーディオフォーカス、イヤホン抜け対応、設定画面 | 11章の受け入れ基準をすべて満たす |

### 進め方の指示

- 段階ごとに作業を区切り、終わったら何を作ったかと実機での確認手順を報告して止まること
- 音のパラメータは `MusicConstants.kt` などに集約し、コードに直接数値を書かない
- 作曲ロジック（音符イベントを返す純粋な関数）、場面の決定、接近の判定には単体テストを書く
- 仕様に曖昧な点があれば、推測で進めず質問すること

## 11. 受け入れ基準とテスト方法

MVPの完成は、以下をすべて確認できた時点とする。

| 項目 | 基準 | 確かめ方 |
| --- | --- | --- |
| 再生開始 | ボタンを押してから1秒以内に音が出る | 実機で10回計測 |
| 画面オフ | 60分間、音切れ・ノイズなし | 画面オフで放置し、イヤホンで聴く。ログでバッファ不足の回数が0であること |
| バッテリー | 60分の再生で、普段使う音楽アプリの1.5倍以内 | 「設定 → 電池」のアプリ別使用量で比較 |
| 場面の切り替え | 5分ごとの切り替えで音切れ・急な変化がない | 実際に歩いて確認 |
| 同じ場所のモチーフ | 同じマスでは常に同じモチーフになる | 単体テスト |
| 接近と到着 | 徒歩で外側の円に入ってから2分以内に接近、内側の円に入ってから1分以内に到着の演出が始まる | 登録地点まで実際に歩いて確認 |
| ばたつき防止 | 円の境目を行き来しても、30分以内に同じ地点の接近演出を繰り返さない | 単体テスト（位置の列を与えて判定） |
| 太陽の高さ | 計算した日の出・日の入り時刻が、公表値と5分以内で一致 | 単体テスト（東京など数地点） |
| 割り込み | 電話着信・他アプリ再生・イヤホン抜けで一時停止し、再開できる | 各操作を実機で確認 |
| プライバシー | 訪問履歴にマスIDと日付以外が含まれず、外部への通信がない | データベースの中身と通信ログを確認 |

開発中は、デバッグ用に現在の場面・フェーズ・一番近い地点までの距離・バッファ残量を画面に出すオプションを用意すること。

# 12. 曲調「フュージョン」（追加仕様）

既存の曲調（癒し系インストゥルメンタル）に加えて、T-SQUARE風の明るいフュージョンを選べるようにする。参照実装は `doc/reference/fusion-session.html`（ブラウザで開くと鳴る。Tone.js 製）。数値はこの参照実装から移植し、`MusicConstants.kt`（または新設する `FusionConstants.kt`）に集約する。参照実装にない値は「仕様外・要調整」と書く。

## 12.1 概要

- 設定画面に「曲調」を追加する。選択肢は「癒し」（既定）と「フュージョン」。`AppSettings` に保存する
- 位置・場面・登録地点・フェーズの仕組みはそのまま使う。変わるのは作曲（音符イベント）と音色だけ
- 生成はこれまでどおりルールベース。AI・通信は使わない
- 作曲はブロック（8小節＝128ステップ、1ステップ＝16分音符）単位で組み立て、`composeUntil(tSec)` で時刻まで音符イベントを返す。チャンク（10秒）の区切りとは独立させる
- 作曲の状態（乱数、直前のリードの音、使い回し中のモチーフ、ブロック番号、熱量）は `copy()` で複製できるようにし、7章の「作り直し」に対応する

## 12.2 基本設定

| 項目 | 値 |
| --- | --- |
| 調 | Aセクション：Dメジャー／Bセクション（サビ）：Eメジャー（全音上に転調） |
| テンポ | 静止 120 BPM／徒歩 132 BPM／乗り物 144 BPM（仕様外・要調整。参照実装の既定は138）。雰囲気「明るい」は +6、「落ち着く」は −12 |
| リズム | ストレート（スウィングなし）の16ビート |
| リードの音域 | MIDI 60〜88 |
| リードの音階 | そのセクションの調の長音階（コードごとの音階ではなく、調に沿わせて歌えるフレーズにする） |
| 太陽 | 全体ローパスを 夜 3500Hz／薄明 5000Hz／昼 7000Hz（仕様外・要調整）。夜は熱量も −0.1（12.5）。調は変えない |

テンポの変更は次のブロックの頭で行う（ブロックの途中では変えない）。

## 12.3 和音進行

各セクション8小節、1小節1和音。王道進行（IV→V→iii→vi）が軸。

| セクション | 調 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| A | D | GM7 | A7 | F♯m7 | Bm7 | Em7 | F♯m7 | GM7 | A7sus4 |
| B | E | AM7 | B7 | G♯m7 | C♯m7 | F♯m7 | G♯m7 | AM7 | A7sus4（Dへ戻る。この小節だけDの長音階） |

和音の構成（ルートからの半音数。鍵盤はルート+48を基準に、45〜54に収まるようオクターブを選ぶ）：

| 種類 | 鍵盤の構成音 | 着地に使う音 | ロングトーンで狙うテンション | 7度（ベース用） |
| --- | --- | --- | --- | --- |
| M7 | 4, 7, 11, 14 | 4, 7, 11, 14 | 2, 11, 9 | 11 |
| 7 | 4, 7, 10, 14 | 4, 10, 7, 14 | 2, 9, 4 | 10 |
| m7 | 3, 7, 10, 14 | 3, 7, 10, 14 | 2, 10, 5 | 10 |
| 7sus4 | 5, 7, 10, 14 | 5, 10, 14, 9 | 2, 9, 5 | 10 |

ベースの根音はルート+36（41を超えたら−12）。

セクションの順番は A, A, B, B をくり返す。2ブロックに1回（奇数番目のブロック）、最後の1小節を「キメ」にする（12.6）。

## 12.4 フェーズとの対応

| フェーズ | フュージョンでの扱い |
| --- | --- |
| 始まり | 最初のブロックはリードを休み、鍵盤・ベース・ハイハットだけ。熱量0.2。2ブロック目から全員 |
| 道中 | A, A, B, B の循環。熱量は12.5で決める |
| 区切り | 道中20分ごとに1回、次のブロックの最後の2小節をキメの連続（ブレイク）にする（仕様外・要調整） |
| 接近 | 次のブロックからBセクション（サビ）に固定。熱量+0.2。モチーフ型に地点のテーマを使う |
| 到着 | 地点のテーマをリードで吹き（ロングトーン・ビブラートあり）、キメ6発のあとトニック（DM9）に着地して2小節伸ばす |
| 滞在 | Aセクション、熱量0.2固定。ドラムはハイハットとキックだけ |
| 終わり | 2小節のキメ → DM9 を鳴らして約12秒でフェードアウト（既存の終わりと同じ長さ） |

## 12.5 熱量

0〜1の値。ブロックごとに決め、リードのフレーズ型の重み、音の明るさ、伴奏の手数を変える。

- 基準値：静止 0.25／徒歩 0.45／乗り物 0.65
- ブロックごとの波：[−0.1, 0, +0.1, +0.25, +0.35, +0.05] を6ブロック周期でくり返す
- なじみ度：初めての場所 +0.05／なじみの場所 −0.1
- 太陽：夜 −0.1（薄明・昼はそのまま）
- 乱数で ±0.05 揺らしてから 0〜1 に収める

## 12.6 リードのフレーズ型

直前の音（初期値 MIDI 72）から始め、下の型を重み付きの乱数で選んでブロックの最後までつなぐ。h は熱量。

| 型 | 内容 | 重み |
| --- | --- | --- |
| 速弾き | 16分で4〜(8+6h)音、長音階を1音ずつ（15%で2音）上るか下る。端に当たったら折り返す。最後は次の8分の頭で着地音（着地に使う音のうち最も近いもの）を2〜5ステップ。着地が小節の頭になるときは50%で8分早く「食う」（和音は次の小節のもの）。熱量0.7以上では40%で32分 | 2 + 3h |
| ロングトーン | テンションを6〜11ステップ伸ばす。70%で1〜2半音下から「しゃくる」。25%で最後に「フォール」。ビブラートあり | 3 − h |
| シーケンス | 4音のパターン（[0,1,2,4] [0,2,1,3] [0,−1,1,2] [2,1,0,−1] の度数）を1度ずつずらして3回（熱量0.5以上で4回）、最後に着地音を3ステップ | 1.2 + 1.5h |
| モチーフ | リズム型に音程の輪郭を載せた短い動機。いったん作ったら使い回し（新しく作るのは18%）、和音が変わっても形を保って移す | 4 − h |
| 回り込み | 次の拍の頭の着地音を、半音上→半音下→着地音で挟む | 0.8 |
| 泣きのハイトーン | MIDI 80〜88 のテンションか着地音へ140msで滑り上がり、8〜13ステップ伸ばす。50%でフォール | 熱量0.4超で 3h、それ以下は0 |
| ひと呼吸 | 2〜(2+3(1−h))ステップの休み | 1.6 − 1.2h |

- モチーフのリズム型：[0,2,4,6] [0,3,6,8,10] [0,2,3,6,8] [0,1,2,4,6,7] [0,3,6,10,14]（ステップ）。輪郭は各音 −1〜+2 度
- **場所との結びつけ**：ブロックで最初に作るモチーフは、場所のモチーフ（マスIDがシード）の音程の動きを輪郭に、リズム型もマスIDから選ぶ。同じマスでは同じ動機でソロが始まる
- 音域の引力：直前の音が77を超えたら下向き、66未満なら上向きを優先する
- **キメ**：最後の小節のステップ [0,3,6,8,10,12] で全員が同じリズムを打つ。リードは着地に使う音を下から順に上っていき、最後の音は4ステップ伸ばしてビブラート。開始の高さは min(直前の音, 72) − 8

## 12.7 伴奏

**鍵盤（シンセブラス）**：小節ごとに下のリズムから選ぶ（[開始ステップ, 長さ]）。「食い」付きは、ステップ14で次の小節の和音を先に弾き、次の小節の頭は弾かない。

| 番号 | リズム | 選ばれる条件 |
| --- | --- | --- |
| 0 | [0,14] | 熱量0.4未満 |
| 1 | [0,3] [6,2] [10,4] [14,2 食い] | 熱量0.4以上 |
| 2 | [0,1] [3,1] [6,1] [8,2] [11,1] [14,2 食い] | 熱量0.75以上 |
| 3 | [0,6] [6,2] [10,2] [14,2 食い] | 熱量0.75未満 |

**ベース**：R=根音、O=オクターブ上、5=5度、7=7度、N=次の小節の根音（食い）。

| 番号 | パターン（[ステップ, 音, 長さ]） | 選ばれる条件 |
| --- | --- | --- |
| 0 | 8分でR ×7、[14,N,2] | 熱量0.4未満 |
| 1 | [0,R,2] [3,R,1] [4,O,1] [6,R,2] [8,5,2] [10,O,1] [11,R,1] [12,7,2] [14,N,2] | 0.4以上 |
| 2 | [0,R,1] [2,O,1] [3,R,1] [4,R,1] [6,O,1] [7,R,1] [8,5,1] [10,O,1] [11,R,1] [12,7,1] [14,N,2] | 0.75以上 |

**ドラム**

- キック：熱量0.4未満 [0,8,10]／0.75未満 [0,6,8,14]／それ以上 [0,3,6,8,11,14]
- スネア：[4,12]。ゴーストノート（強さ0.14）を [2,7,9,15] に確率 0.25+0.5h で
- ハイハット：熱量0.45未満は8分、それ以上は16分。強さは4分の頭0.8／8分0.5／16分0.3。30%でステップ14をオープン
- フィル：ブロックの最後の小節（キメでないとき）、ステップ12から（熱量0.6超は8から）スネア→ハイタム→ミッドタム→ロータム→スネアの16分
- クラッシュ：ブロックの頭。熱量0.6超では5小節目の頭にも

## 12.8 音色（追加する楽器）

| パート | 作り方 |
| --- | --- |
| リード（EWI風） | ノコギリ波2本（±4セント）＋1オクターブ下の矩形波（−12dB）。ローパス −12dB/oct、Q 2.2。フィルターのエンベロープは基準 800+700×熱量 Hz から 2.8オクターブ上へ、立ち上がり0.03秒・減衰0.3秒・保持0.65。音量のエンベロープは立ち上がり0.018秒・減衰0.25秒・保持0.8・余韻0.12秒。**モノフォニック**（1つの発音体で音程を滑らせる） |
| リードの奏法 | グライド：16分以下12ms／それ以外35ms／ハイトーン140ms。しゃくり：1〜2半音下で鳴らし始め、30ms後から80msで目標の音へ。フォール：終わりの160ms前から4半音下へ200msで。ビブラート：6.3Hz、深さ ±(20+15×熱量)セント（仕様外・要調整）を、音の頭から0.5秒（または音の長さの6割）かけて深くする |
| シンセブラス | ノコギリ波2本（±5セント）→ ローパス2600Hz → コーラス（1.2Hz）。立ち上がり0.012秒・減衰0.5秒・保持0.35・余韻0.35秒。和音は下の音から7msずつずらして鳴らす |
| ベース | 三角波 → ローパス820Hz。立ち上がり0.01秒・減衰0.3秒・保持0.5・余韻0.1秒。**音ごとに別の発音体**（同じ発音体で音程を切り替えるとプチ音が出るため） |
| キック | サイン波、38Hzの4オクターブ上から35msで下降、減衰0.32秒 |
| スネア | ピンクノイズ → バンドパス1900Hz。減衰は 0.1+0.12×強さ 秒 |
| ハイハット | ホワイトノイズ → ハイパス7000Hz、右0.35。減衰 30ms+15ms×強さ（オープンは220ms）。**リバーブに送らない**（常に「サー」と鳴り続けるのを防ぐ） |
| タム | サイン波 190／145／108Hz、減衰0.3秒 |
| クラッシュ | ホワイトノイズ → ハイパス4500Hz、減衰1.4秒 |

空間系と送り量：

- ディレイ：付点8分、フィードバック0.3、ローパス2400Hz
- リバーブ：残響約2.4秒（既存のFDNリバーブを流用してよい）
- 送り量（リバーブ／ディレイ）：リード 0.3／0.36、シンセブラス 0.3／0.06、ベース 0.04／0、ドラム 0.1／0
- 定位：シンセブラス −0.3、リード +0.1、ほかは中央
- 最後に全体ローパス（太陽）→ コンプレッサー（−18dB、3:1）→ リミッター（−1dB）
- 音量の目安（参照実装のdB）：リード −8、リードの下の層 −20、シンセブラス −12、ベース −6、キック −6、スネア −5、ハイハット −25、タム −8、クラッシュ −24

## 12.9 人間らしさ

- 発音時刻の揺れ：キック ±1.5ms、ベース ±3ms、スネア・タム ±3ms、鍵盤 ±6ms、ハイハット ±6ms、リード ±4ms
- バックビート（ステップ4と12）のスネアは +5ms 遅らせる
- 強さ ±10%、キックとタムの音程 ±2%
- 揺れは作曲側ではなく合成の直前に、ブロックごとのシードで付ける（同じシード → 同じ結果）
- 同じ楽器の発音は時刻順に並べ直し、4ms以上空ける。リードは次の音の3ms前までに必ず離す

## 12.10 実装の注意

- 音符イベント：既存の `NoteEvent` とは別に、リード用（グライド・しゃくり・フォール・ビブラートの情報を持つ）とドラム用（種類・強さ・音程の倍率）のイベントを追加する
- リードの発音体はチャンクをまたいで状態（位相・音程・エンベロープ・フィルター）を引き継ぐ。既存の `Voice.copy()` と同じ方式で複製できるようにする
- 処理の重さの目安：参照実装（Web、1コア）では17秒ぶんを約8秒で生成できた。端末でリアルタイム比0.5以下を目標にし、足りない場合はリードの下の層とゴーストノートを省く
- 単体テストで確かめること
  - 同じシードなら同じ音符イベント
  - リードが音域内（60〜88）で、調の外の音が全体の3%以下（回り込みの半音を除く）
  - 同じ楽器の発音時刻が単調に増える
  - 熱量が0〜1に収まる
  - 接近で次のブロックからBセクションになり、到着でトニックに着地する
  - 同じマスでは最初のモチーフが同じになる

## 12.11 実装ステップ

| 段階 | 作るもの | 完了条件 |
| --- | --- | --- |
| 6a. 音色 | 12.8の楽器と空間系、フュージョン用のデモ再生（固定の進行と固定の熱量） | デモが途切れず鳴り、プチ音・バリ音がない |
| 6b. 作曲 | 12.3〜12.7、12.9。フェーズ・場面・地点との対応（12.4、12.5） | 単体テストが通り、デモ台本で熱量と接近・到着の違いが聞き分けられる |

## 12.12 ユーザーと決めたこと

1. **再生中の切り替え**：再生中に曲調を変えたら、再生位置から約2秒でフェードアウトし、1秒以上先のチャンクを捨てて、新しい曲調の作曲エンジンで「始まり」から作り直す。場面と登録地点の判定状態は引き継ぐ。登録地点の内側の円にいるときは、再生開始時と同じく到着の演出なしで滞在に入る。停止中の切り替えは次の再生から反映する。終わり（停止ボタンのフェードアウト）の最中の切り替えは無視する
2. **デモ再生**：曲調の設定に従う。デモ台本（場面の時刻や地点）は曲調によらず同じ
3. **夜**：全体ローパスを暗くし（夜3500Hz）、熱量を −0.1 する。調は変えない
4. **通知・ロック画面**：サブタイトルに常に曲調を添える。「おまかせ再生中・癒し」「おまかせ再生中・フュージョン」「デモ再生中・癒し」「デモ再生中・フュージョン」。接近中の文言（例「いつもの公園に近づいています」）は曲調を添えずこれまでどおり

2. デモ再生（開発用）でも曲調の設定に従うか
3. 夜の扱い（案：フィルターを暗くするだけ／案：キーを下げる）
4. 通知やロック画面のサブタイトルに曲調を出すか（例：「おまかせ再生中・フュージョン」）
