# Ekifu — 通勤のサウンドスケープ

移動中の「場所」を楽譜にして、癒し系インストゥルメンタルを端末上で自動生成・再生する Android アプリ。
仕様は [doc/SPEC.md](doc/SPEC.md)、要点は [CLAUDE.md](CLAUDE.md)。

## 構成

| ディレクトリ | 内容 |
| --- | --- |
| `engine/` | 音楽エンジン（Android 非依存の Kotlin）。作曲 `Composer`、合成 `Synth`、デモ台本 `DemoScript`、パラメータ `MusicConstants.kt` |
| `app/` | Android アプリ（Jetpack Compose）。段階1ではデモ再生画面のみ |
| `.github/workflows/android-debug-apk.yml` | 単体テストとデバッグ用 APK のビルド |

## ビルド

- GitHub へ push すると Actions が `:engine:test` と `:app:assembleDebug` を実行し、APK を成果物（Artifacts）`ekifu-debug-apk-<番号>` としてアップロードする
- 手元では `./gradlew :engine:test :app:assembleDebug`（JDK 17 と Android SDK が必要）
- デバッグ署名の鍵 `app/debug.keystore` をリポジトリに入れてあるので、新しい APK をそのまま上書きインストールできる（デバッグ専用。公開用の署名には使わない）

## 実機での確認手順

### 段階1：音の再現

**APK を入れる**

1. GitHub のリポジトリで「Actions」タブ →「デバッグ用APKのビルド」→ 最新の成功した実行（緑のチェック）を開く
2. ページ下部「Artifacts」の `ekifu-debug-apk-<番号>` をダウンロードする（zip。GitHub へのログインが必要）
3. zip を展開して `app-debug.apk` を取り出し、スマホに移す（スマホのブラウザで直接ダウンロードしてもよい。その場合はファイルアプリで zip を展開する）
4. スマホで `app-debug.apk` を開く。「提供元不明のアプリ」の確認が出たら、そのアプリ（ファイル・Chrome など）からのインストールを許可する
5. 「通勤のサウンドスケープ」を起動する（Android 8.0 以上）

**聴いて確かめる**（イヤホン推奨。段階1は画面をつけたまま聴く。再生中は画面が自動で消えない）

1. 「デモ再生」を押す。すぐに音が出る
2. 画面の「聞きどころ」と「デモの流れ」を見ながら、次の違いを聞き分ける

| 時刻の目安 | フェーズ | 聞こえ方 |
| --- | --- | --- |
| 0:00〜1:05 | 始まり | I→IV の繰り返し。音数が少なく、夜明け前なので低くこもった音 |
| 1:05〜 | 道中 | vi から始まる8つの和音の進行。30秒ごとに場面が変わり、ベルで場所のモチーフが鳴る。テンポ・音数・明るさが8拍かけて変わる |
| 3:05ごろ | 区切り | 道中が2分続いたので IV→Vsus→IV→I を1回 |
| 4:00〜 | 接近（公園・落ち着く） | IV→Vsus→IV→I の繰り返し。公園のテーマがプラックで小さく鳴る。ゆっくり、やわらかい音へ |
| 4:30〜 | 到着 → 滞在 | テーマをベルで鳴らし、I を長く鳴らして着地。その後 I→IV→vi→IV |
| 5:15〜 | 離れる → 道中 | テーマを一度だけ静かに鳴らして道中へ戻る |
| 5:45〜6:30 | 駅（懐かしい） | 接近→到着→滞在。ディレイの残響が長く、滞在の進行が vi→IV→I→iii |
| 7:00〜 | 電車 | テンポが速く（1拍0.8秒）音数が増える |
| 9:00〜 | 職場（明るい） | 接近→到着→滞在。メロディが高い音域まで広がり、ベルの飾りが増える。以後は滞在が続く |
| 停止ボタン | 終わり | I を鳴らして約12秒でフェードアウトし、止まる |

3. 途切れ・プチッというノイズがないこと、デバッグ表示の「音切れ（アンダーラン）」が 0 回のままであることを確認する

※ 地点への接近・到着は台本の時刻の後、次の和音の切り替え（最大約9秒後）で反映される。
