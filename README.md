# ekifu

移動中の「場所」を楽譜にして、癒し系インストゥルメンタルを端末上で自動生成・再生する Android アプリ。
仕様は [doc/SPEC.md](doc/SPEC.md)、要点は [CLAUDE.md](CLAUDE.md)。

## 構成

| ディレクトリ | 内容 |
| --- | --- |
| `engine/` | 音楽エンジン（Android 非依存の Kotlin）。作曲 `Composer`、合成 `Synth`、チャンク生成とバッファ `ChunkStream`、デモ台本 `DemoScript`、パラメータ `MusicConstants.kt` |
| `app/` | Android アプリ（Jetpack Compose）。再生はフォアグラウンドサービス `PlaybackService`（Media3 MediaSession）で行う |
| `.github/workflows/android-debug-apk.yml` | 単体テストとデバッグ用 APK のビルド |

## ビルド

- GitHub へ push すると Actions が `:engine:test` と `:app:assembleDebug` を実行し、APK を成果物（Artifacts）`ekifu-debug-apk-<番号>` としてアップロードする
- 手元では `./gradlew :engine:test :app:assembleDebug`（JDK 17 と Android SDK が必要）
- デバッグ署名の鍵 `app/debug.keystore` をリポジトリに入れてあるので、新しい APK をそのまま上書きインストールできる（デバッグ専用。公開用の署名には使わない）

## 実機での確認手順

### 段階1：音の再現

**APK を入れる**

1. GitHub のリポジトリで「Actions」タブ →「デバッグ用APKのビルド」→ 最新の成功した実行（緑のチェック）を開く
2. ページ下部「Artifacts」の `ekifu-debug-apk-<番号>` をダウンロードする（zip。GitHub へのログインが必要）
3. zip を展開して `app-debug.apk` を取り出し、スマホに移す（スマホのブラウザで直接ダウンロードしてもよい。その場合はファイルアプリで zip を展開する）
4. スマホで `app-debug.apk` を開く。「提供元不明のアプリ」の確認が出たら、そのアプリ（ファイル・Chrome など）からのインストールを許可する
5. 「ekifu」を起動する（Android 8.0 以上）

**聴いて確かめる**（イヤホン推奨。段階2からは画面を消しても鳴り続ける）

1. 「デモ再生」を押す。すぐに音が出る
2. 画面の「聞きどころ」と「デモの流れ」を見ながら、次の違いを聞き分ける

| 時刻の目安 | フェーズ | 聞こえ方 |
| --- | --- | --- |
| 0:00〜1:05 | 始まり | I→IV の繰り返し。音数が少なく、夜明け前なので低くこもった音 |
| 1:05〜 | 道中 | vi から始まる8つの和音の進行。30秒ごとに場面が変わり、ベルで場所のモチーフが鳴る。テンポ・音数・明るさが8拍かけて変わる |
| 3:05ごろ | 区切り | 道中が2分続いたので IV→Vsus→IV→I を1回 |
| 4:00〜 | 接近（公園・落ち着く） | IV→Vsus→IV→I の繰り返し。公園のテーマがプラックで小さく鳴る。ゆっくり、やわらかい音へ |
| 4:30〜 | 到着 → 滞在 | テーマをベルで鳴らし、I を長く鳴らして着地。その後 I→IV→vi→IV |
| 5:15〜 | 離れる → 道中 | テーマを一度だけ静かに鳴らして道中へ戻る |
| 5:45〜6:30 | 駅（懐かしい） | 接近→到着→滞在。ディレイの残響が長く、滞在の進行が vi→IV→I→iii |
| 7:00〜 | 電車 | テンポが速く（1拍0.8秒）音数が増える |
| 9:00〜 | 職場（明るい） | 接近→到着→滞在。メロディが高い音域まで広がり、ベルの飾りが増える。以後は滞在が続く |
| 停止ボタン | 終わり | I を鳴らして約12秒でフェードアウトし、止まる |

3. 途切れ・プチッというノイズがないこと、デバッグ表示の「バッファ不足」が 0 回のままであることを確認する

※ 地点への接近・到着は台本の時刻の後、次の和音の切り替え（最大約9秒後）で反映される。

### 段階2：バックグラウンド再生

APK の入れ方は段階1と同じ（新しい番号の `ekifu-debug-apk-<番号>` を上書きインストール。アプリ名が「ekifu」に変わる）。

1. 「ekifu」を起動して「デモ再生」を押す。Android 13 以上では通知の許可を求められるので「許可」を選ぶ（通知とロック画面の操作に必要）
2. 1秒以内に音が出ることを確認する
3. 通知欄に「ekifu / デモ再生中」の通知が出ていることを確認する。公園に近づく場面（約4分）では「いつもの公園に近づいています」に変わる
4. **画面オフ**：電源ボタンで画面を消し、イヤホンで30分間聴き続ける。音切れ・ノイズがないこと
5. **ロック画面**：画面を消したまま電源ボタンで画面をつけ、ロック画面のプレーヤーで一時停止 → 再開する。止めた位置から続きが鳴ること
6. **ほかのアプリ**：ホームに戻ったり別のアプリを開いたりしても鳴り続けること（音楽アプリなど、ほかに音を出すアプリは使わない。割り込みへの対応は段階5）
7. アプリに戻り、デバッグ表示の「バッファ不足」が 0 回であることを確認する。「バッファ残量」はおおむね 30〜60 秒のあいだで増減する
8. 「停止」を押す。I を鳴らして約12秒でフェードアウトし、通知が消えること
9. （任意）Bluetooth イヤホンの再生/一時停止ボタンでも操作できること

※ パソコンにつないで `adb logcat -s ekifu` を見ると、バッファ不足が起きたときに「バッファ不足 N 回」と出る。

### 段階3：おまかせ再生

APK は新しい番号の `ekifu-debug-apk-<番号>` を上書きインストールする。

**準備**：スマホの位置情報をオンにしておく。

1. 「ekifu」を起動し、大きな「再生」を押す。位置の許可を求められたら「アプリの使用中のみ」を選ぶ（「正確」「おおよそ」のどちらでもよい）。通知の許可も「許可」
2. 1秒以内に音が出る。最初は仮の場面で鳴り、位置が取れると（通常は数秒〜20秒ほど）その場所のモチーフがベルで鳴る
3. 画面で次を確かめる：場面（例「歩いている・初めての場所・昼」）、「次の場面まで 4:59」の残り時間。デバッグ表示の「マス」（6桁の英数字）、「速さ」、「位置：○分前に取得」
4. **移動して確かめる**（30分以上）：画面を消し、イヤホンで聴きながら歩く・電車に乗るなどして移動する
   - 5分ごとに場面が切り替わっても音切れしない
   - マスが変わるとベルで新しいモチーフが鳴る。同じマスのままならベルは鳴らず、テンポや明るさだけがゆっくり変わる
   - 乗り物ではテンポが速く、止まっているとゆっくりになる
   - 地下などで位置が取れないときは、直前の場面がそのまま続く
5. **同じ場所に戻る**：出発した場所に戻ると、出発時と同じモチーフがベルで鳴る（6桁のマスが同じなら同じメロディ）
6. アプリに戻って「バッファ不足」が 0 回であることを確かめる
7. 一時停止すると「次の場面まで」の表示が消える（位置の取得も止まる）。再開すると位置を取り直して場面が決まる
8. **位置の許可なし**：スマホの設定でアプリの位置の許可を「許可しない」にして「再生」→「位置の許可がないため…」の注意が出て、5分ごとに架空の場所のモチーフに変わる
9. 夜（日没後しばらくたってから）に再生すると、和音が低く、こもった音になる

※ 同じマスを10日以上訪れると「なじみの場所」になり、パッド中心で音数が減る。訪問履歴にはマスIDと日付しか保存しない。
※ 開発用の「デモ再生」は画面下の「開発用」欄にある。
