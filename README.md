# ekifu

移動中の「場所」を楽譜にして、インストゥルメンタル（曲調は「癒し」と「フュージョン」）を端末上で自動生成・再生する Android アプリ。
仕様は [doc/SPEC.md](doc/SPEC.md)、要点は [CLAUDE.md](CLAUDE.md)。

## 構成

| ディレクトリ | 内容 |
| --- | --- |
| `engine/` | 音楽エンジン（Android 非依存の Kotlin）。曲調「癒し」は作曲 `Composer`・合成 `Synth`（`MusicEngine`）、曲調「フュージョン」は作曲 `FusionComposer`・合成 `FusionSynth`（`FusionEngine`）。チャンク生成とバッファ `ChunkStream`、デモ台本 `DemoScript`、パラメータ `MusicConstants.kt`・`FusionConstants.kt` |
| `app/` | Android アプリ（Jetpack Compose）。再生はフォアグラウンドサービス `PlaybackService`（Media3 MediaSession）で行う |
| `.github/workflows/android-debug-apk.yml` | 単体テストとデバッグ用 APK のビルド |

## ビルド

- GitHub へ push すると Actions が `:engine:test` と `:app:assembleDebug` を実行し、APK を成果物（Artifacts）`ekifu-debug-apk-<番号>` としてアップロードする
- 手元では `./gradlew :engine:test :app:assembleDebug`（JDK 17 と Android SDK が必要）
- デバッグ署名の鍵 `app/debug.keystore` をリポジトリに入れてあるので、新しい APK をそのまま上書きインストールできる（デバッグ専用。公開用の署名には使わない）

## 実機での確認手順

### 段階1：音の再現

**APK を入れる**

1. GitHub のリポジトリで「Actions」タブ →「デバッグ用APKのビルド」→ 最新の成功した実行（緑のチェック）を開く
2. ページ下部「Artifacts」の `ekifu-debug-apk-<番号>` をダウンロードする（zip。GitHub へのログインが必要）
3. zip を展開して `app-debug.apk` を取り出し、スマホに移す（スマホのブラウザで直接ダウンロードしてもよい。その場合はファイルアプリで zip を展開する）
4. スマホで `app-debug.apk` を開く。「提供元不明のアプリ」の確認が出たら、そのアプリ（ファイル・Chrome など）からのインストールを許可する
5. 「ekifu」を起動する（Android 8.0 以上）

**聴いて確かめる**（イヤホン推奨。段階2からは画面を消しても鳴り続ける）

1. 「デモ再生」を押す。すぐに音が出る
2. 画面の「聞きどころ」と「デモの流れ」を見ながら、次の違いを聞き分ける

| 時刻の目安 | フェーズ | 聞こえ方 |
| --- | --- | --- |
| 0:00〜1:05 | 始まり | I→IV の繰り返し。音数が少なく、夜明け前なので低くこもった音 |
| 1:05〜 | 道中 | vi から始まる8つの和音の進行。30秒ごとに場面が変わり、ベルで場所のモチーフが鳴る。テンポ・音数・明るさが8拍かけて変わる |
| 3:05ごろ | 区切り | 道中が2分続いたので IV→Vsus→IV→I を1回 |
| 4:00〜 | 接近（公園・落ち着く） | IV→Vsus→IV→I の繰り返し。公園のテーマがプラックで小さく鳴る。ゆっくり、やわらかい音へ |
| 4:30〜 | 到着 → 滞在 | テーマをベルで鳴らし、I を長く鳴らして着地。その後 I→IV→vi→IV |
| 5:15〜 | 離れる → 道中 | テーマを一度だけ静かに鳴らして道中へ戻る |
| 5:45〜6:30 | 駅（懐かしい） | 接近→到着→滞在。ディレイの残響が長く、滞在の進行が vi→IV→I→iii |
| 7:00〜 | 電車 | テンポが速く（1拍0.8秒）音数が増える |
| 9:00〜 | 職場（明るい） | 接近→到着→滞在。メロディが高い音域まで広がり、ベルの飾りが増える。以後は滞在が続く |
| 停止ボタン | 終わり | I を鳴らして約12秒でフェードアウトし、止まる |

3. 途切れ・プチッというノイズがないこと、デバッグ表示の「バッファ不足」が 0 回のままであることを確認する

※ 地点への接近・到着は台本の時刻の後、次の和音の切り替え（最大約9秒後）で反映される。

### 段階2：バックグラウンド再生

APK の入れ方は段階1と同じ（新しい番号の `ekifu-debug-apk-<番号>` を上書きインストール。アプリ名が「ekifu」に変わる）。

1. 「ekifu」を起動して「デモ再生」を押す。Android 13 以上では通知の許可を求められるので「許可」を選ぶ（通知とロック画面の操作に必要）
2. 1秒以内に音が出ることを確認する
3. 通知欄に「ekifu / デモ再生中」の通知が出ていることを確認する。公園に近づく場面（約4分）では「いつもの公園に近づいています」に変わる
4. **画面オフ**：電源ボタンで画面を消し、イヤホンで30分間聴き続ける。音切れ・ノイズがないこと
5. **ロック画面**：画面を消したまま電源ボタンで画面をつけ、ロック画面のプレーヤーで一時停止 → 再開する。止めた位置から続きが鳴ること
6. **ほかのアプリ**：ホームに戻ったり別のアプリを開いたりしても鳴り続けること（音楽アプリなど、ほかに音を出すアプリは使わない。割り込みへの対応は段階5）
7. アプリに戻り、デバッグ表示の「バッファ不足」が 0 回であることを確認する。「バッファ残量」はおおむね 30〜60 秒のあいだで増減する
8. 「停止」を押す。I を鳴らして約12秒でフェードアウトし、通知が消えること
9. （任意）Bluetooth イヤホンの再生/一時停止ボタンでも操作できること

※ パソコンにつないで `adb logcat -s ekifu` を見ると、バッファ不足が起きたときに「バッファ不足 N 回」と出る。

### 段階3：おまかせ再生

APK は新しい番号の `ekifu-debug-apk-<番号>` を上書きインストールする。

**準備**：スマホの位置情報をオンにしておく。

1. 「ekifu」を起動し、大きな「再生」を押す。位置の許可を求められたら「アプリの使用中のみ」を選ぶ（「正確」「おおよそ」のどちらでもよい）。通知の許可も「許可」
2. 1秒以内に音が出る。最初は仮の場面で鳴り、位置が取れると（通常は数秒〜20秒ほど）その場所のモチーフがベルで鳴る
3. 画面で次を確かめる：場面（例「歩いている・初めての場所・昼」）、「次の場面まで 4:59」の残り時間。デバッグ表示の「マス」（6桁の英数字）、「速さ」、「位置：○分前に取得」
4. **移動して確かめる**（30分以上）：画面を消し、イヤホンで聴きながら歩く・電車に乗るなどして移動する
   - 5分ごとに場面が切り替わっても音切れしない
   - マスが変わるとベルで新しいモチーフが鳴る。同じマスのままならベルは鳴らず、テンポや明るさだけがゆっくり変わる
   - 乗り物ではテンポが速く、止まっているとゆっくりになる
   - 地下などで位置が取れないときは、直前の場面がそのまま続く
5. **同じ場所に戻る**：出発した場所に戻ると、出発時と同じモチーフがベルで鳴る（6桁のマスが同じなら同じメロディ）
6. アプリに戻って「バッファ不足」が 0 回であることを確かめる
7. 一時停止すると「次の場面まで」の表示が消える（位置の取得も止まる）。再開すると位置を取り直して場面が決まる
8. **位置の許可なし**：スマホの設定でアプリの位置の許可を「許可しない」にして「再生」→「位置の許可がないため…」の注意が出て、5分ごとに架空の場所のモチーフに変わる
9. 夜（日没後しばらくたってから）に再生すると、和音が低く、こもった音になる

※ 同じマスを10日以上訪れると「なじみの場所」になり、パッド中心で音数が減る。訪問履歴にはマスIDと日付しか保存しない。
※ 開発用の「デモ再生」は画面下の「開発用」欄にある。

### 段階4：登録地点

APK は新しい番号の `ekifu-debug-apk-<番号>` を上書きインストールする（段階3の訪問履歴はそのまま残る）。

**地点を登録する**

1. 再生画面右上の「登録地点」→「地点を追加」
2. 名前を入れる（例：いつもの公園）
3. 位置を決める：「現在地で登録」を押すか、地図をタップする。タップした所に印と2つの円（外側＝接近、内側＝到着）が出る
4. 雰囲気（落ち着く／明るい／懐かしい）を選び、接近の円（200〜1000m、既定500m）と到着の円（50〜300m、既定100m）をスライダーで決める
5. 「試聴」でテーマ（最後は主音で終わる短いメロディ）を聴く。「別のメロディにする」で作り直せる
6. 「保存」。一覧に出ることを確かめる（最大20件。編集・削除・試聴は一覧から）

**近づいて確かめる**（地点から2km以上離れた所から始める）

1. 「再生」を押し、画面を消してイヤホンで聴きながら、登録した地点へ歩いて向かう
2. 地点の1.5km以内に入ると、デバッグ表示の「位置の取得間隔」が「1分」に変わる（通常は5分）
3. **接近**：外側の円に入ってから2分以内に、IV→Vsus→IV→I の繰り返しになり、地点のテーマがプラックで小さく聞こえる（落ち着く地点ならテンポがゆっくり、音がやわらかくなる）。通知のサブタイトルが「○○に近づいています」に変わる
4. **到着**：内側の円に入ると、テーマがベルで鳴り、I を長く鳴らして着地する。その後は滞在（I→IV→vi→IV、懐かしい地点なら vi→IV→I→iii）
5. **離れる**：外側の円の1.2倍より外に出ると、テーマが一度だけ静かに鳴り、16拍かけて道中に戻る
6. **ばたつき防止**：外側の円の境目を行き来しても、離れてから30分以内は接近の演出が繰り返されない
7. **最初から中にいる**：内側の円の中で「再生」を押すと、始まりではなく滞在から始まる（最初の位置が取れてから十数秒後）
8. 画面の「一番近い登録地点：○○（1.2km）」の表示と、デバッグ表示の「判定」（○○に接近中／到着）を確かめる

※ 地図は表示しているあいだだけ地図画像をネットから取る。登録した地点の座標は端末内にだけ保存し、外部に送らない。
※ 家の中で試すなら、到着の円を小さく、接近の円を大きくした地点を近所に登録して歩くと確かめやすい。

### 段階5：仕上げ

APK は新しい番号の `ekifu-debug-apk-<番号>` を上書きインストールする。

**変わったところ**

- 再生画面の右上に「地点」「設定」。デバッグ表示と開発用のデモ再生は、既定では隠れている（設定 →「デバッグ表示」をオンにすると出る）
- 設定：訪問履歴の消去（確認つき）、デバッグ表示の切り替え、プライバシーの説明
- 電話・他アプリの再生・イヤホン抜けで一時停止する（自動では再開しない。ロック画面・通知・アプリから再開する）。通知音では止まらず、音量が一時的に下がる

**割り込みの確かめ方**

1. 再生中に電話をかけてもらう → 着信で一時停止する。通話が終わっても止まったまま。再開ボタンで続きから鳴る
2. 再生中に音楽アプリや動画を再生する → ekifu が一時停止する
3. 再生中に通知音が鳴る（メッセージの受信など）→ 止まらずに、通知音のあいだだけ音量が下がり、鳴り終わると元に戻る
4. 有線イヤホンを抜く／Bluetooth イヤホンの接続を切る → スピーカーから鳴らずに一時停止する
5. 通話中に ekifu の再生を押しても鳴らない

### 受け入れ基準（仕様書11章）の確かめ方

| 項目 | 確かめ方 |
| --- | --- |
| 再生開始（1秒以内） | 「再生」を10回押して計測する。パソコンにつないで `adb logcat -s ekifu` を見ると、1回ごとに「再生開始まで N ms」と出る（AudioTrack に書き始めるまで。実際に聞こえるのはこれに約0.1〜0.5秒足した頃） |
| 画面オフ60分 | 画面オフで60分放置し、イヤホンで音切れ・ノイズがないか聴く。`adb logcat -s ekifu` に「バッファ不足」が一度も出ないこと。設定でデバッグ表示をオンにすると、再生画面の「バッファ不足」も 0 回 |
| バッテリー | 60分再生したあと「設定 → 電池」のアプリ別使用量で、普段の音楽アプリの60分と比べて1.5倍以内 |
| 場面の切り替え | 実際に歩いて、5分ごとの切り替えで音切れ・急な変化がないこと（段階3の手順） |
| 同じ場所のモチーフ | 単体テスト `SceneDeciderTest.returningToSamePlaceGivesSameMotif`、`MotifsTest.sameGridAlwaysGivesSameMotif`（GitHub Actions で毎回実行） |
| 接近と到着 | 登録地点まで歩いて、外側の円に入ってから2分以内に接近、内側の円に入ってから1分以内に到着の演出（段階4の手順） |
| ばたつき防止 | 単体テスト `PlaceTrackerTest.boundaryFlappingDoesNotRepeatApproachWithin30Minutes` |
| 太陽の高さ | 単体テスト `SunTest`（東京・札幌・那覇の日の出・日の入りが国立天文台の公表値と1分以内） |
| 割り込み | 上の「割り込みの確かめ方」 |
| プライバシー | 下の手順でデータベースを取り出し、`visits` 表にマスIDと日付しかないこと、`places` 表は登録した地点だけであることを確かめる。通信は地点登録の地図の表示中だけ（設定 → アプリ → ekifu → モバイルデータ の使用量が、地図を開かなければ増えない） |

データベースの取り出し方（デバッグ用 APK なので可能）：

```
adb exec-out run-as jp.fmt.ekifu cat databases/ekifu.db > ekifu.db
adb exec-out run-as jp.fmt.ekifu cat databases/ekifu.db-wal > ekifu.db-wal   # 最近の書き込みはこちらに入っている
sqlite3 ekifu.db "SELECT * FROM visits;"   # gridId と day だけ
sqlite3 ekifu.db "SELECT name, mood FROM places;"
```

### 段階6a：フュージョンの音色（SPEC 12章）

APK は新しい番号の `ekifu-debug-apk-<番号>` を上書きインストールする。

1. 設定 →「デバッグ表示」をオンにする
2. 再生画面の下「開発用」→「フュージョンの音色デモ」を押す（132 BPM、A→A→B→B のくり返し。1ブロック＝8小節＝約14.5秒）
3. 画面に和音（例「A・GM7」）と熱量が出る。熱量はブロックごとに 0.3 → 0.6 → 0.9 と変わる
4. 聴いて確かめる（イヤホン推奨）
   - 途切れず鳴り、プチッ・バリッという音がない
   - リード（EWI風）：しゃくり上げて伸ばす音、16分・32分の速弾き、半音上下から回り込む音、140msで滑り上がるハイトーンと最後のフォール、伸ばす音のビブラート
   - シンセブラス（やや左）、ベース、ドラム（キック・スネア・ハイハット・タム・クラッシュ）
   - 熱量 0.3 はハイハットが8分でキック少なめ、0.9 は16分・キックが多く、スネアのゴーストノートとフィルが増える
   - 3・4ブロック目（B）は全音上に転調し、2ブロックに1回、最後の小節がキメ（全員で同じリズム）
5. 「停止」で DM9 の和音を鳴らして約12秒でフェードアウトする
6. 画面を消しても途切れない。デバッグ表示の「バッファ不足」が 0 回

### 段階6b：フュージョンの作曲（SPEC 12章）

APK は新しい番号の `ekifu-debug-apk-<番号>` を上書きインストールする。6a の「音色デモ」はなくなり、「フュージョンのデモ再生」に置き換わった。

1. 設定 →「デバッグ表示」をオン。再生画面の下「開発用」→「フュージョンのデモ再生（自宅 → 公園 → 駅 → 職場）」
2. 画面に台本の区間名（例「いつもの公園に近づく」）、和音（例「B・AM7」）、熱量、テンポが出る。デバッグ表示のフェーズも見ながら聴く
3. 聞き分けること（時刻は目安）

| 時刻 | フェーズ | 聞こえ方 |
| --- | --- | --- |
| 0:00〜0:15 | 始まり | リードなし。鍵盤・ベース・ハイハットだけ（熱量0.2） |
| 0:15〜 | 道中 | リードがアドリブ（速弾き・ロングトーン・シーケンス・モチーフ・回り込み・ハイトーン）。A→A→B→B、Bで全音上へ転調。2ブロックに1回、最後の小節がキメ |
| 2:25ごろ | 区切り | 最後の2小節がキメの連続（ブレイク） |
| 2:40〜 | 道中（信号待ち） | テンポ120に落ち、熱量が下がって手数が減る |
| 4:10ごろ | 接近（公園・落ち着く） | サビ（B）に固定、熱量が上がる。テンポ −12。モチーフに公園のテーマの形が出る |
| 4:40ごろ | 到着 | テーマをロングトーンで吹き、キメ6発のあと DM9 に着地して2小節伸ばす |
| 5:00〜 | 滞在 | A、熱量0.2。ドラムはハイハットとキックだけ |
| 5:30ごろ | 道中（公園を離れる） | A から道中に戻る。最初のモチーフで公園のテーマの形が一度出る |
| 7:10〜 | 乗り物 | テンポ144、熱量が上がる |
| 8:30〜 | 職場（明るい） | 接近・到着・滞在。テンポ +6 |

4. 「停止」で、次の16分からキメを2小節 → DM9 に着地して約12秒でフェードアウトする
5. 画面オフでも途切れず、デバッグ表示の「バッファ不足」が 0 回

### 段階6c：曲調の切り替え（SPEC 12章）

APK は新しい番号の `ekifu-debug-apk-<番号>` を上書きインストールする。開発用欄の「フュージョンのデモ再生」はなくなり、デモ再生も「曲調」の設定に従う（6b の確認は、曲調をフュージョンにしてから「デモ再生」で行う）。

1. 設定 →「曲調」に「癒し」（既定）と「フュージョン」がある。選んだ曲調はアプリを閉じても残る
2. 停止中に「フュージョン」を選んで再生画面に戻り、「再生」を押す。通知とロック画面のサブタイトルが「おまかせ再生中・フュージョン」になる（デモ再生なら「デモ再生中・フュージョン」、癒しなら「…・癒し」）
3. 再生したまま設定を開いて曲調を変える
   - 約2秒でフェードアウトし、新しい曲調の「始まり」から鳴る（フュージョンの始まりはリードなし・熱量0.2、癒しの始まりは I→IV のくり返し）
   - 通知のサブタイトルの曲調がすぐ変わる
   - 一時停止中に変えた場合は、再開したときに約2秒のフェードアウトのあと新しい曲調で鳴る
4. デモ再生中に変えると、台本は続きから（デバッグ表示の台本の区間がそのまま進む）
   - 「いつもの公園に着く」〜「公園を離れる」のあいだに変えると、到着の演出なしで新しい曲調の滞在から鳴る
   - 「いつもの公園に近づく」のあいだに変えると、新しい曲調の始まりのあと接近に入る（癒しは始まりが1分あるので、そのあいだに台本の到着が来れば到着の演出になる）
5. おまかせ再生で登録地点の内側の円にいるときに変えると、到着の演出なしで滞在に入る。外側の円（接近中）なら始まりのあと接近に入る。通知の「〇〇に近づいています」には曲調は付かない
6. 「停止」を押したあと（フェードアウト中）に変えても、いまの音はそのまま終わる。次の再生から新しい曲調になる
7. 切り替えを何度くり返しても途切れず、デバッグ表示の「バッファ不足」が 0 回

### フュージョンのキメとつなぎ（段階6cのあとの追加）

APK は新しい番号の `ekifu-debug-apk-<番号>` を上書きインストールする。設定で曲調を「フュージョン」、「デバッグ表示」をオンにして、開発用欄の「デモ再生」で確かめる。キメ・つなぎの小節では、再生画面の和音の後ろに「（キメ：3連打）」「（つなぎ：盛り上げ）」のように型が出る。

1. キメ（道中・接近の2ブロックに1回、最後の小節）が毎回同じリズムではなくなる。型は5種類で、同じ型は続かない
   - 基本（参照実装の6発）／3・3・2／裏から（小節の頭を空けて入る）／3連打（ダダダ・ダダダ・ダーン）
   - ブレイク：頭の1発で伴奏が止まり、リードだけが駆け上がって伸ばし、最後の1拍のスネアで次のブロックへ
   - 区切り（2:25ごろ）は2小節続けて違う型
2. フェーズの変わり目の前の小節に「つなぎ」が入る（時刻はデモの目安）

| 時刻 | 変わり目 | つなぎ |
| --- | --- | --- |
| 0:13ごろ | 始まり → 道中 | 呼び込み：小節の後半からスネアの16分がだんだん強くなり、ベースが次の和音へ歩いて上がる |
| 4:08ごろ | 道中 → 接近 | 盛り上げ：小節まるごとスネアの16分で盛り上げ、リードが16分で駆け上がる |
| 4:40ごろ | 接近 → 到着 | ブレイク：頭の1発で止まり、リードのハイトーンだけが残る。最後の1拍のスネアで到着へ |
| 5:28ごろ | 滞在 → 道中（公園を離れる） | 呼び込み |

3. 到着 → 滞在（DM9 を伸ばしてそのまま）と、区切りとの行き来にはつなぎを入れない。道中が続くあいだの小節もこれまでどおり
4. 位置の判定が小節の直前（最後の約2秒）に来たときは、つなぎなしで次のブロックから変わる（デモの最後の職場への到着がこれに当たる）
